# android-xml-canvas 功能全景设计方案

> 版本：v1.0（2026-10-31）
> 目的：把「做一个能真正用在 Android 布局开发里的可视化工具」这件事拆清楚——现在有什么、还差什么、先后顺序怎么排。
> 读者：本项目开发者（你）。不是对外宣传文案，是实现路线图。

---

## 1. 产品定位

**一句话**：浏览器/手机上打开就能改 Android 布局 XML 的工具，改完直接写回项目目录，导出即可用。

三类使用场景，按重要性排序：

| 场景 | 用户动作 | 对工具的硬要求 |
|---|---|---|
| A. 手边没 IDE | 打开工程目录 → 点开 layout → 拖控件/改属性 → 保存回原文件 | 解析/写回不能破坏原 XML（注释、顺序、命名空间） |
| B. 快速试版式 | 从模板起步 → 拉出 2~3 个屏 → 导出 PNG/res 给同事看 | 组件够用、预览够像、导出够快 |
| C. 让 AI 改界面 | 描述需求 → AI 产出 XML → 画布上微调 | AI 输出必须能被本工具的容错解析器吃下 |

**不做的事**（明确边界，避免路线图失控）：
- 不做 Gradle 构建 / APK 打包（成本极高，用户有 Android Studio）
- 不做真机调试（adb 桥接价值低于维护成本）
- 不做完整 Android Studio 替代（不碰 Java/Kotlin 源码编辑）

## 2. 现状盘点（M1–M25i，975 测试）

### 2.1 已经能用

**编辑核心**
- 自写容错 XML 解析器（Node/浏览器都能跑，半个 XML 不白屏）
- 画布渲染 + 点选 + 属性面板双向回写
- 撤销/重做（含合并标记）、格式化（保留注释）、行号高亮、光标行联动
- 分层树（选中/拖拽/上下移/锁定/删除）、容器层级限制

**布局能力**
- ConstraintLayout 基础约束（上下左右/居中）+ 约束面板 + 一键自动约束
- 线性/帧/相对/滚动容器、常用 Material 组件库
- 多设备尺寸预设、缩放 0.4~1.5、明暗主题、系统栏开关

**资源**
- 形状（shape）生成器：圆角/描边/渐变/ripple
- 图标：Material 图标字库 → 生成 vector drawable
- 已生成资源面板（改名/删除/编辑）、res 包导出（zip）、整包另存（layout+drawable+values）
- 缺失 drawable 引用检查

**工程**
- 工作目录：APK（native bridge）/ 浏览器（File System Access）/ 内存三级兜底
- 项目列表 + 项目结构树（异步加载）、打开/保存（写回原路径）/另存、新建空项目

**预览与输出**
- 运行调试视图：涟漪、输入框、开关/勾选、SeekBar、Spinner、列表假数据
- 导出 PNG / SVG、多语言界面（中文 / English）

**AI**
- OpenAI 兼容协议面板（5 家预设），key 只存本地，自动带当前 XML 上下文，回复可一键替换画布

### 2.2 半成品 / 有明显缺口

| 缺口 | 现状 | 影响 |
|---|---|---|
| include / merge | 只读展开 + 提示「去原文件改」 | 多文件工程改不动 |
| values 资源（@color/@string/@dimen/@style） | 能读、能导出，缺可视化编辑与跳转 | 硬编码色值满天飞 |
| 主题（Theme.Material3.\*） | 只有预览用主题预设，不读工程主题 | 预览颜色与真机不符 |
| 多语言资源预览 | 无 | 中文布局在英文环境下没验证过 |
| Guideline / Barrier / Chain / Ratio | 解析层支持有限，缺可视化编辑 | 复杂自适应布局做不了 |
| 复制/粘贴/多选/成组 | 只有单节点操作 | 重复结构要手搓 |
| 自动保存 / 历史版本 | 无 | 手滑丢工作 |
| 工程整体导入（含 gradle 目录结构） | 只能开单文件或简易项目 | 真实项目接入门槛高 |
| Lint / 适配检查 | 有基础 lint（结构/命名） | 上线前检查靠人眼 |

## 3. 目标功能架构

七个域，按「先能干活 → 再干得好 → 最后智能化」排序。

### 域 A｜编辑核心（地基，最高优先）

| 功能 | 说明 | 优先级 |
|---|---|---|
| A1 XML 往返保真 | 写回时保留注释/属性顺序/命名空间/缩进风格；只改被编辑的属性 | P0 |
| A2 撤销栈持久化 | 刷新/切文件不丢历史（sessionStorage + 容量上限） | P0 |
| A3 多选与成组 | Shift 点选、框选、成组移动、批量改属性 | P1 |
| A4 复制/粘贴/重复 | Ctrl+C/V/D，跨文件粘贴，id 自动去重 | P1 |
| A5 命令面板 | Ctrl+K：插入组件、跳到图层、切设备、导出 | P2 |
| A6 快捷键体系 | 可查表、可改键（对齐 Android Studio 直觉） | P2 |

### 域 B｜布局与约束能力（决定能不能做真界面）

| 功能 | 说明 | 优先级 |
|---|---|---|
| B1 约束可视化编辑 | 画布上拖锚点连线（已有约束绘制雏形，补删除/改目标/偏移气泡） | P0 |
| B2 Guideline / Barrier | 拖出参考线、Barrier 按控件组动态对齐 | P1 |
| B3 Chain 与权重 | 一键横向/纵向 Chain、weighted chain、packed/spread | P1 |
| B4 比例与偏置 | layout_constraintDimensionRatio、水平/垂直 bias 滑杆 | P1 |
| B5 对齐吸附与参考线 | 拖动时显示与他控件边缘/基线的对齐提示并吸附 | P1 |
| B6 自动布局建议 | 「这屏太挤/太随意」→ 建议改 ConstraintLayout 或加间距 | P2 |
| B7 布局转代码片段 | 选中子树 → 生成 Jetpack Compose 片段（辅助迁移） | P2 |

| C5 图片资源导入 | 拖入 png/webp → 自动命名、压缩、生成 @drawable 引用 | P1 |
| C6 矢量编辑器增强 | 现有图标编辑器补路径节点编辑、多色、状态色 | P2 |
| C7 九宫格 / layer-list | 生成 .9.png 说明、layer-list/selector 可视化 | P2 |

| 功能 | 说明 | 优先级 |
|---|---|---|
| D1 include 可编辑 | 点 include 跳转源文件；改完回来保持滚动位置与选中 | P0 |

| 功能 | 说明 | 优先级 |
|---|---|---|

| F2 截图转布局 | 上传设计稿/截图 → 生成 XML（需多模态模型） | P2 |
| F3 布局体检 | AI 审当前 XML：层级过深、重复结构、硬编码色值 | P2 |
| F4 prompt 导出 | 把当前画布导出成给 Claude Code/Cursor 的提示词（M3E 的强项，保留） | P1 |

| 功能 | 说明 | 优先级 |
|---|---|---|
| G1 自动保存与恢复 | 每 30s 写 IndexedDB，崩溃/刷新可恢复；提示「恢复上次未保存」 | P0 |
| G2 本地版本历史 | 每次显式保存留快照（最近 20 个），可对比/回滚 | P1 |

## 4. 关键设计决策

### 4.1 数据模型：以「文件」为真相，以「工程模型」为索引

```
Workspace（工作目录）
└─ Project（一个 res 根）
   ├─ layouts: Map<path, LayoutDoc>      // 原文 + 解析树 + 版本号
   ├─ resources: ResourceTable           // color/string/dimen/style/drawable
   ├─ generated: Map<name, xml>          // 本工具生成的 drawable
   └─ refGraph: 引用图（谁引用了谁）
```

- **原文永不丢**：LayoutDoc 同时保存 `rawText` 与 `tree`，写回时只做「属性级 patch」，不重新序列化整棵树（这是保真的前提）。
- **增量解析**：文件内容 hash 未变则复用解析结果；大文件（>2000 行）走 worker（后期）。
- **引用图**用于三件事：改名波及（D3）、缺失资源检查（已有）、删除前影响提示。

### 4.2 写回策略：以「最小 diff」为原则

1. 只 patch 被改属性所在的那一行/那一处
2. 新增属性 → 插到同类属性附近（保持分组可读）
3. 删除属性 → 删整行（不留空行堆）
4. 结构变更（插入/删除/移动节点）→ 只动相关子树文本
5. 每次写回前生成 diff，保存成功后可「查看本次改动」

> 现有 `writebackAttrs` 已是这个思路，缺的是「结构变更」和「diff 预览」两半。

### 4.3 预览真实度分级（明确告知用户，别假装 1:1）

| 级别 | 覆盖 | UI 表现 |
|---|---|---|
| L1 精确 | 尺寸/间距/颜色/文字/基础样式 | 无标记 |
| L2 近似 | 阴影/涟漪/字体度量/系统组件皮肤 | 角落「≈」角标，hover 说明 |
| L3 模拟 | 列表滚动、页面跳转、动画 | 运行调试视图里才开 |
| L4 不支持 | 自定义 View、复杂主题继承、data binding | 明确提示「此项需真机验证」 |

这条要写进 UI，避免「预览好看但真机不一样」的信任崩塌。

## 6. 优先级矩阵（价值 / 成本）

```
高价值 ┤  C1 资源管理    B1 约束编辑
       │  A1 往返保真    G1 自动保存
       │  D1 include
       ├──────────────────────────────
低价值 ┤  E4 屏幕矩阵    C7 九宫格
       │  F2 截图转布局  B7 Compose
       └──────┬──────────────┬────────
            低成本          高成本
```

**先做左上角（高价值低成本）**：A1、G1、C1、D1。
**别碰右下角**：截图转布局、Compose 迁移都很诱人，但会吃掉两三个迭代且不解决「能不能干活」。

## 7. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| XML 写回毁文件 | 用户改一个属性，整个文件重排/丢注释 | A1 必须最先做；写回前 diff + 备份副本（`.axv.bak`） |
| 预览失真导致不信任 | 「预览好看，真机丑」 | 4.3 分级标注 + 明确的「不支持」提示 |
| 功能贪多而不深 | 每个域都半成品 | 每阶段只锁 4–5 个里程碑，验收标准写死 |
| APK 与网页行为分叉 | 同一功能两端表现不同 | 核心逻辑全在 `lib/xml/*`（已做到），UI 层只做适配 |
| AI 输出不可解析 | 生成半个 XML、非法属性 | 解析器容错 + 应用前 lint + 可回滚（已有撤销栈） |
| 性能随项目变大下降 | 结构树/画布卡 | G5 性能预算 + 树虚拟化 + 大文件 worker |

## 8. 每个模块的验收标准（Checklist 模板）

**写完一个功能，至少满足：**
1. 有纯逻辑单测（lib 层，不依赖 DOM）
2. 有契约测试或浏览器实测记录（UI 层）
3. `npx tsc --noEmit` + `npx next build` 通过
4. 手机（APK）与网页两端行为一致，或明确说明差异
5. 载入真实项目文件不崩（大文件、含中文注释、含命名空间前缀）
6. 出错有可读提示，不白屏（CanvasBoundary / 解析失败卡片已有先例）
